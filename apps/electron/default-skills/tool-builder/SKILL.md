# Tool Builder

Gamma 仅提供 Agent。旧版 Chat HTTP 工具注册与执行链已退役；本 Skill 保留名称，帮助升级工作区不再进入旧流程，而不是提供另一套工具运行时。

## 接入流程

1. 明确用户要调用的服务、操作、参数和结果；能从上下文推断的不要重复询问。
2. 检查当前 Agent 工具及已有 MCP，优先复用。不要为了单次 API 请求创建持久工具；可在授权范围内通过现有工具完成。
3. 需要长期接入时，优先采用服务官方 MCP。先查询已配置连接；依据官方资料核验 transport、命令、公开地址和认证方式。
4. 仅用 Gamma 提供的 MCP 管理工具配置、验证连接。配置同名但不同的连接前说明影响并取得确认，不直接编辑 MCP 配置文件。
5. Token、授权 Header、环境变量密钥和 OAuth client secret 必须由用户在 MCP 管理界面的安全凭据流程保存，不索要或写入明文。OAuth 由用户显式授权。
6. 没有合适的 MCP 且需要实现新的集成时，先给出最小实现方案与接口边界，由用户确认后再执行；不要把方案描述成已经可用的工具。
7. 验证握手、工具发现及一条低风险调用，并如实报告尚未验证的能力。发送、发布、付费或权限变化需另行确认。

## 旧版配置的处理

- 不再创建、修改或读取 `chat-tools.json` 作为活动工具注册表，也不引导用户切换 Chat 或打开 Chat 工具开关。
- 不删除用户原有工具文件或秘密。用户要求迁移时，先确认范围，只读取必要的非敏感接口定义；凭据重新通过安全界面保存。
- 自定义/安装的用户 Skill 不属于本 Skill 的自动清理范围。
